# Reference data provenance and reuse

Normal generation runs offline against the [reference package lock](../../contracts/reference-package-lock.json). Each selected package has a SHA-256 and byte count; each public source inside the package records its original URL, content hash and archive members. A changed reference fails the lock check until it is explicitly reviewed and relocked. No patient or worker is copied from a public person record.

| Package | Origin and selection |
| --- | --- |
| [Person name weights](../../references/person-name-weights.json) | SSA aggregate counts: birth decades 1920–2009, top 400 curated names per decade/source series. Census 2010: top 12,000 surname weights and aggregate category weights with documented small-cell smoothing. |
| [Clinical code releases](../../references/clinical-code-releases.json) | Three hundred stable adult-scope ICD-10-CM codes and 100 stable ICD-10-PCS codes, across seven applicable release intervals: October 2022, April/October 2023, April/October 2024, April/October 2025. Total 2,800 version rows. |
| [Hospital references](../../references/hospital-reference-catalog.json) | Two hundred explicitly local product, ingredient, unit, supply, service, account and denial entries, plus role/credential metadata. Fictional model inputs, not licensed payer contracts or prescribing guidance. |

The [SSA download description](https://www.ssa.gov/oact/babynames/limits.html) explains the aggregate naming data and suppression of very small counts. The official ZIP returned HTTP 403 in this environment. The importer therefore records a **disclosed public mirror** at [hackerb9/ssa-baby-names, pinned commit 0b1a131](https://github.com/hackerb9/ssa-baby-names/tree/0b1a1316457d55447d1a1f7bfe57ee15e53cc2f0), rather than claiming a successful official download or identical bytes to today's SSA file. The mirror's aggregate content hash is `7c8ca3c1ef72de0b0222a6c62bff494cc60c1d37e41b0745ede6570250e07f9a`. Original integer counts are retained after selection and curated registration-label exclusions are recorded.

The [Census 2010 surname page](https://www.census.gov/topics/population/genealogy/data/2010_surnames.html) describes national aggregate name counts, not individual identities. The ZIP was downloaded directly from the Census server and hashed. Self-report is independently generated first; category weights guide surname selection probabilistically, with cross-population mixing. They never impute a person's self-report or disease. Suppressed small cells receive a declared minimal smoothing weight. These weights are a vocabulary-generation choice, not a demographic-classification model.

Official diagnosis/procedure archives come from the [CMS ICD-10 release page](https://www.cms.gov/medicare/coding-billing/icd-10-codes) and the dated CDC ICD-10-CM directories. October/April validity boundaries are separate. Late-2025 care uses the FY2026 interval rather than a calendar-year-2025 file. Catalog knowledge starts conservatively at release effectiveness; no earlier publication claim is invented.

Some CMS annual PCS URLs for FY2023/FY2024 currently alias their April-updated ZIPs. The importer explicitly excludes **all added, deleted or revised codes named in those addenda** before selecting the unchanged common subset for the earlier interval. This avoids backdating new/revised April content. Annual CM originals are separately available from CDC. Code descriptions are retained from each relevant file; source archives and selected membership are auditable. The selection is a bounded adult-service vocabulary, not a complete coding-policy implementation.

The [importer](../../scripts/import_public_references.py) keeps full public downloads in ignored `data/public-reference-cache/`. The committed packages are bounded metadata/reference inputs, not generated business populations. The local catalog uses `HOSPITAL_LOCAL` explicitly; it does not claim to be LOINC, RxNorm, CARC, or a vendor's real tenant catalog.

Refresh references only through an intentional review: inspect the source/provenance change, regenerate the bounded package, review reference semantics and downstream budget effects, relock, regenerate affected candidates, review the new identity sample if it changes, and rerun the acceptance command. A network refresh is never part of an ordinary generation run.
